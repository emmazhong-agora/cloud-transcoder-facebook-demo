# Agora Cloud Transcoder to Facebook Lab

A local web demo for testing Agora Cloud Transcoder output to Facebook Live, including stream keys generated by the Meta Live Video API. It preserves the complete signed RTMPS URL and records redacted API diagnostics.

The browser provides configuration, task management, and an optional RTC source preview. A Node.js server keeps Agora REST credentials and Meta access tokens on the server.

## Quick start

Requirements: Node.js 22 or later, an Agora project with Cloud Transcoding enabled, and a Facebook account or Page eligible to use Facebook Live.

```sh
npm ci
cp .env.example .env
```

Fill in your local `.env`:

| Variable | Purpose |
| --- | --- |
| `AGORA_APP_ID` | Agora project App ID |
| `AGORA_CUSTOMER_ID` | Agora REST Customer ID |
| `AGORA_CUSTOMER_SECRET` | Agora REST Customer Secret |
| `META_TARGET_TYPE` | `profile` for a personal profile, or `page` for a Facebook Page |
| `META_USER_ACCESS_TOKEN` | Personal profile access token; required only for profile-mode Meta API operations |
| `META_PAGE_ACCESS_TOKEN` | Page access token; required only for Page-mode Meta API operations |
| `META_PAGE_ID` | Required for Page mode; leave empty for a personal profile |
| `META_GRAPH_VERSION` | Graph API version, initially `v26.0` |
| `PORT` | Local HTTP port, initially `8787` |

Use the appropriate Meta token for the selected target. If you already have a complete streaming URL, you can leave the Meta token fields empty and skip the Meta API buttons. An Agora REST Customer Secret is different from an App Certificate. This demo does not require an App Certificate or generate RTC tokens.

```sh
npm start
```

Open [http://localhost:8787](http://localhost:8787). The server binds to `127.0.0.1` only. Restart it after editing `.env`.

For development, `npm run dev` watches `.env`, `server.mjs`, and `public/`. Node's `--watch-path` support depends on the operating system; use `npm start` when unavailable. An open page automatically refreshes its local session marker and retries once if a server restart invalidated that marker. Upstream errors and network failures are not automatically retried.

The Agora Web SDK is served from the installed npm package. Fonts optionally load from Google Fonts, with local fallbacks.

## Test a broadcast

Follow the four numbered steps. The page shows one step at a time, with **Continue** and **Back** controls.

1. **Prepare your source.** Enter your Agora App ID, RTC channel, publisher UID, and transcoder input tokens. Keep your publisher sending media. Optionally expand the source preview to monitor that publisher or use this browser's camera. Browser publisher mode uses the same UID as the source; monitor mode uses a different UID.
2. **Connect Facebook.** Choose **Create or manage a broadcast with the Meta API**, then click **Create Facebook broadcast & get URL**. The returned Live Video ID and complete streaming URL appear automatically. To reuse a saved broadcast, refresh its details instead of creating another one. Alternatively, choose **I already have a Facebook streaming URL** and paste it; this path needs no Meta token.
3. **Start the stream.** Review the source, destination host, and video settings, then click **Start streaming**. Guided mode automatically applies step 1 and step 2 to the request while preserving encoding and layout edits. Creating a cloud task is billable and requires confirmation. Success opens step 4; it does not publish Facebook automatically.
4. **Preview & go live.** Open **Live Producer**, select **Streaming software**, and verify incoming video and audio. Check Facebook's audience setting, then tick the preview confirmation and click **Publish to Facebook**. The viewer URL is shown separately for sharing. If you supplied a URL manually, preview and publish in the Live Producer page where you obtained it, and copy the viewer link there.

After testing, expand **Finish the test / Manage existing tasks** in step 4. End the Facebook broadcast and stop the Agora task; refresh the task status to confirm it stopped. Closing the browser or server stops neither service. Saved tasks can also be reached directly through step 4 in the navigation.

The included `demo-channel`, UID `12345`, zero-filled sample stream key, and angle-bracket tokens are fictional placeholders. Replace them before testing. The steps check configuration, not whether RTC media is currently arriving; use the previews to verify reception.

### Preview versus viewer page

| Page or status | Meaning |
| --- | --- |
| Live Producer | Host dashboard for receiving and previewing an unpublished stream |
| Viewer page / `permalink_url` | Audience destination after publishing, subject to the broadcast's privacy settings |
| Meta `UNPUBLISHED` | The broadcast has not been published; it does not by itself indicate reception success or failure |
| Agora `IN_PROGRESS` | The transcoding task is running; this does not prove Facebook has received media |

Use Live Producer to test reception before publishing. **Publish to Facebook** requests `LIVE_NOW` and asks for confirmation. Check the Facebook audience setting, such as Only me, before publishing.

A visible placeholder image proves that output is reaching Facebook, but does not prove that the source publisher's camera video is being received. The RTC preview in this demo displays the input, not Facebook's CDN output.

### RTC tokens and UIDs

- `audioInputs[].rtc.rtcUid` and `videoInputs[].rtc.rtcUid` identify the source publisher, initially `12345` in the sample.
- Agora's Cloud Transcoder reference specifies generating its input-channel RTC token with UID `0`, because Agora assigns the transcoder's channel UID. Keep the source publisher UID in `rtcUid`.
- The browser uses a separate RTC token for its own UID. In monitor mode, use a UID different from the source publisher, initially `12346`.
- Token-expiry events prompt for a replacement browser token. Use **Renew token** before expiry, or leave and rejoin with a new token after expiry. Transcoder tokens must be managed separately.

### Form and JSON behavior

The default **Guided** mode applies current source fields and the complete destination URL automatically when you click **Start streaming**. You do not need to click Apply. Encoding and layout changes in the JSON editor remain intact; guided mode updates RTC inputs and the first output URL only. The review shows the effective request's source, output hosts and video settings.

For compatibility testing, expand **Advanced: encoding, request JSON & compatibility tests** in step 3. Choose **Custom** to send the edited JSON without applying form fields. In Custom mode, the JSON is authoritative, so review all destinations and inputs. **Apply form to JSON** remains available as an explicit editing action.

Form fields and raw request JSON are automatically saved in this browser's local storage, including incomplete JSON edits. The saved draft includes RTC tokens, stream keys, streaming URLs, and live video IDs. It remains local to the browser and origin; `localhost` and `127.0.0.1` have separate drafts. Clear this site's browser data when you want to remove the draft.

Reloading restores the selected step and settings. It does not automatically join RTC, create or publish a live video, or start polling. The preview confirmation is deliberately reset so you check reception again before publishing. Existing cloud tasks still need to be managed explicitly.

## Facebook broadcast setup

Step 2 creates or selects the Facebook destination; step 3 starts the Agora media sender; step 4 previews, publishes and shares the broadcast. The Meta API is an optional convenience for managing Facebook broadcasts. If you already have a valid streaming URL, choose the manual path and use Live Producer directly. Account configuration and API error queries are under expandable settings.

Profile mode uses `META_USER_ACCESS_TOKEN` and `/me`; it does not require `META_PAGE_ID` or fall back to a Page token. Page mode uses `META_PAGE_ACCESS_TOKEN` and `META_PAGE_ID`. Profile publishing requires `publish_video`; account eligibility and any additional requirements are checked by Meta.

| Operation | API behavior |
| --- | --- |
| Check account and permissions | Read `/me?fields=id,name`; profile mode also reads `/me/permissions` |
| Create unpublished live video | `POST /me/live_videos` for profiles or `POST /{page-id}/live_videos` for Pages, with `status=UNPUBLISHED` |
| Query status and URL | Read `id,status,secure_stream_url,permalink_url` from the live video object |
| Query errors | Read `/{live-video-id}/errors` |
| Publish | Update the live video with `status=LIVE_NOW` |
| End | Update the live video with `end_live_video=true` |

A returned streaming URL fills the destination field and is applied automatically in Guided mode. Step 2 displays the API's Live Video ID. Step 4 displays the copyable viewer URL and Live Producer preview URL. Creating a broadcast requests its permalink and automatically queries once if Meta omits it. If the link is still unavailable, use **Refresh status & links** for the existing ID rather than creating another broadcast. Viewer links are saved with the browser draft; editing the Live Video ID clears the previous link to avoid mixing broadcasts. The Graph API version can be changed in the UI. Meta errors are preserved in the redacted diagnostics; the demo does not bypass permission or account eligibility checks.

## Compare stream-key behavior

Change one variable per test and stop the previous sender before reusing a stream key.

| Test | Configuration | Observe |
| --- | --- | --- |
| Baseline | Live Producer-generated URL | Reception, preview, and service states |
| API-generated key | Same source and encoding; Meta's original `secure_stream_url` | Whether only the API-generated URL fails |
| Field type | Same URL; switch `streamUrl` between array and string | Schema compatibility |
| Independent sender | OBS or FFmpeg using the same original URL, with Agora output stopped first | Separate destination/key issues from the Agora output path |

The demo initially uses an array for compatibility testing. The current Agora REST reference documents `streamUrl` as a string. The type switch in step 3 advanced settings is explicit; the demo does not silently normalize it.

Keep the URL, live video object, and Live Producer page from the same broadcast. Do not assume a stream key prefix always equals the API's Live Video ID. Keep signed parameters such as `s_bl`, `s_ow`, `s_psm`, `s_pub`, `s_sw`, `s_tids`, `s_vt`, and `a` unchanged. Do not encode, decode, remove, or reorder them.

## Diagnostics and local state

- Diagnostic logs redact RTC tokens, builder tokens, streaming URLs, Meta access tokens, and authorization headers. Exported reports may still contain account names, IDs, channel names, and task metadata; review them before sharing.
- The JSON editor and streaming URL fields contain unredacted values. Avoid screenshots or recordings of those fields when sharing publicly.
- `.runtime/tasks.json` retains task IDs, App IDs, builder tokens, and states, with file mode `0600`. It enables query and destroy after server restarts. Keep it private and do not delete it while tasks still need to be managed.
- A destroy response can be `STOPPING`, so task records remain available for subsequent queries.
- A create timeout can leave the cloud outcome unknown. Check request IDs before attempting another create.

This is a local diagnostic tool with fixed upstream hosts, Host/Origin checks, and a local request marker. It has no multi-user authentication. Publishing the source on GitHub does not deploy the backend. GitHub Pages cannot run this Node.js server; add authentication and deployment controls before hosting it publicly.

## Validation

```sh
npm test
```

Tests use HTTP and SDK mocks. They cover guided/custom request preparation, publication confirmation gates, draft progress recovery, exact signed URL bytes, array/string payloads, the task lifecycle, authentication, task recovery, session renewal, rejection before upstream effects, redaction, Meta target selection, RTC subscriptions, and track cleanup. They do not create billable tasks or publish broadcasts. Test credentials and signatures are deliberately fictional.

Before publishing, follow [PUBLISHING.md](PUBLISHING.md). Commit `.env.example`, not `.env` or `.runtime/`.
